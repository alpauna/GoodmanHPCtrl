# Bug #2: Manual override bypasses startup lockout — CNT can be activated during sensor stabilization period

**Severity:** High (safety)
**Date discovered:** 2026-02-22
**Affected files:** `src/GoodmanHP.cpp`, `include/GoodmanHP.h`, `src/WebHandler.cpp`, `src/HttpsServer.cpp`
**Fixed in:** `4e357ff` ("Block manual override during startup lockout to prevent CNT activation")

---

## Summary

The manual override feature does not check the startup lockout flag, allowing a user to enable manual override and turn on the compressor contactor (CNT) during the 180-second startup lockout period. This lockout exists to prevent output activation before temperature sensors have stabilized and the state machine has assessed conditions. A secondary issue in the short cycle protection condition makes it ineffective for the first 30+ seconds after boot.

## Impact

- Compressor can be activated before sensors have stabilized, bypassing safety checks (low temp protection, LPS fault, high suction temp, RV fail)
- The 180-second startup lockout — designed to prevent exactly this — is rendered ineffective by manual override
- Short cycle protection at boot is not meaningful: `initPin()` sets `_changeOffTick = millis()`, so the 30-second short cycle timer starts from boot time, not from a real CNT off event

## Root Cause Analysis

### Bug 1: `setManualOverride()` does not check `_startupLockout`

`GoodmanHP::setManualOverride()` (`GoodmanHP.cpp:1442`) accepted `on = true` without verifying that the startup lockout period had completed:

```cpp
void GoodmanHP::setManualOverride(bool on) {
    // No _startupLockout check!
    if (on && !_manualOverride) {
        _manualOverride = true;
        _manualOverrideStart = millis();
        // ...
    }
}
```

The `update()` function (line 157–166) correctly returns early during `_startupLockout`, but `setManualOverride()` is called from the web API handlers — a completely separate code path that bypasses `update()`.

### Bug 2: `setManualOutput()` does not check `_startupLockout`

`GoodmanHP::setManualOutput()` (`GoodmanHP.cpp:1467`) also had no startup lockout check, so even if `setManualOverride()` had been blocked, a stale manual override session from a previous boot could theoretically allow output activation:

```cpp
String GoodmanHP::setManualOutput(const String& name, bool on) {
    if (!_manualOverride) return "Manual override not active";
    // No _startupLockout check!
    OutPin* pin = getOutput(name);
    // ...
}
```

### Bug 3: Short cycle protection condition is overly permissive

The short cycle check in `setManualOutput()` used an AND condition that made it ineffective after 30 seconds:

```cpp
if (offElapsed < 5UL * 60 * 1000 && offElapsed < _cntShortCycleMs) {
```

After boot, `_changeOffTick` is set to `millis()` by `initPin()`. At 75 seconds post-boot:
- `offElapsed = 75000ms`
- `offElapsed < _cntShortCycleMs` = `75000 < 30000` = **false**
- Entire AND condition is **false** — short cycle does not block

The `5UL * 60 * 1000` (5-minute) term is redundant since `_cntShortCycleMs` (30s) is always shorter. The only purpose it served was in `isShortCycleProtectionActive()` where it determines how long the "SC" pill shows on the dashboard — but that's a display concern, not a safety gate.

### Why the normal code path was safe

The `update()` function has a startup lockout guard at the very top (line 157–166):

```cpp
void GoodmanHP::update() {
    if (_startupLockout) {
        if (millis() - _startupTick >= STARTUP_LOCKOUT_MS) {
            _startupLockout = false;
        } else {
            return;  // Skip ALL state machine logic
        }
    }
    if (_manualOverride) {
        return;  // Skip state machine when in manual mode
    }
    // ... rest of state machine
}
```

This correctly blocks the automatic state machine during lockout. But the manual override API (`setManualOverride` + `setManualOutput`) is invoked directly from web request handlers, never passing through `update()`.

## Fix Applied

Four changes across four files:

### 1. `setManualOverride()` returns error during startup lockout (`GoodmanHP.cpp`)

Changed return type from `void` to `String`. Added startup lockout check at the top:

```cpp
String GoodmanHP::setManualOverride(bool on) {
    if (on && _startupLockout) {
        uint32_t remainSec = (getStartupLockoutRemainingMs() + 999) / 1000;
        Log.warn("HP", "Manual override blocked: startup lockout (%us remaining)", remainSec);
        return "Startup lockout: " + String(remainSec) + "s remaining";
    }
    // ... rest of function
    return "";
}
```

### 2. `setManualOutput()` blocks during startup lockout (`GoodmanHP.cpp`)

Defense-in-depth — even if manual override is somehow active during lockout:

```cpp
String GoodmanHP::setManualOutput(const String& name, bool on) {
    if (!_manualOverride) return "Manual override not active";
    if (_startupLockout) return "Startup lockout active";
    // ...
}
```

### 3. Simplified short cycle condition (`GoodmanHP.cpp`)

Removed redundant 5-minute window from the AND condition:

```cpp
// Before:
if (offElapsed < 5UL * 60 * 1000 && offElapsed < _cntShortCycleMs) {

// After:
if (offElapsed < _cntShortCycleMs) {
```

### 4. Web API handlers return error to client (`WebHandler.cpp`, `HttpsServer.cpp`)

Both HTTP and HTTPS `/pins` POST handlers now check the return value and send a 409 response with the error message:

```cpp
String err = _hpController->setManualOverride(on);
if (err.length() > 0) {
    resp["error"] = err;
    // ... send 409 Conflict
    return;
}
```

The `pins.html` frontend already handled `d.error` responses (line 158), reverting the checkbox and displaying an alert — no frontend changes needed.

### 5. Header declaration updated (`GoodmanHP.h`)

```cpp
// Before:
void setManualOverride(bool on);

// After:
String setManualOverride(bool on);
```

## Files Changed

- `include/GoodmanHP.h` — `setManualOverride()` return type `void` -> `String`
- `src/GoodmanHP.cpp` — Startup lockout checks in `setManualOverride()` and `setManualOutput()`, simplified short cycle condition
- `src/WebHandler.cpp` — Error handling for manual override toggle
- `src/HttpsServer.cpp` — Error handling for manual override toggle (HTTPS path)

## How to Reproduce

1. Upload firmware and reboot the device
2. Immediately open the Pins page in the browser (within 180 seconds of boot)
3. Enable "Manual Override" checkbox
4. Toggle CNT output ON
5. **Before fix:** CNT activates during startup lockout — compressor starts before sensors stabilize
6. **After fix:** Checkbox reverts with alert "Startup lockout: Xs remaining"

## Lessons Learned

- Web API endpoints that control outputs must enforce the same safety invariants as the state machine — they share the same physical outputs but take completely different code paths
- Defense-in-depth: both the entry point (`setManualOverride`) and the action (`setManualOutput`) should independently verify preconditions
- `initPin()` setting `_changeOffTick = millis()` at boot creates a synthetic "off event" that starts the short cycle timer from boot — this is acceptable for the normal state machine (which has its own startup lockout), but exposed a gap when manual override bypassed that lockout
- Compound conditions with AND (`a && b`) where `b` is strictly tighter than `a` make `a` dead code — simplify to just `b`
